## Current and target behavior

The architecture already requires an operator-owned, fail-closed gateway interceptor, authoritative trusted provider-profile catalog, exact inspected OpenShell worker policy, and enforcing outer CNI before private work. No such gateway extension, catalog, signed intent contract, deployment policy, or live mutation proof exists in this scaffold. A provisioner's valid `provider:write` token can natively reach profile-write RPCs despite the application's own rejection. The disposable OpenShell spike uses no private source and does not close this gap. This CR is an **implementation intake for the existing OPS-11 design**, not a changed permission grant or approval to enable private stages.

Implement the selected gateway's fail-closed route governance so a signed intent authorizes **one logical create** and covers the entire canonical effective `CreateSandboxRequest` after patches, including exact workspace/name/request ID, metadata, all inline `spec` fields including provider **names**, image/policy, and explicitly empty workload template, caller driver config, and service exposures. The signed intent envelope and durable ledger also bind the authenticated controller identity-provider registration, issuer, and subject. A separate signed intent-envelope map binds each name to its trusted pre-create immutable provider ID/resource version, profile digest, and approved credential/grant generation; matching post-create desired-identity receipts are required while source/model credentials and egress remain closed. Pin the v0.1.5 or upgraded protobuf descriptor and normalization; reject unknown fields until reviewed. The selected gateway/driver independently rejects caller-supplied external/foreign mounts. Bind returned immutable sandbox ID and full persisted spec plus actual Pod/PVC/service inventory before releasing Job API, broker, model, or direct-source readiness. An uncertain create stays closed: reconcile by signed workspace/name first; only a policy-bounded identical same-`request_id` retransmission under the **same authenticated controller identity-provider registration, issuer, and subject, RPC/workspace, current attempt, original/effective payload, stable interceptor transformation, and signed intent** may retrieve the one original result inside the pinned gateway's proven replay window. `REQUEST_ID_PAYLOAD_MISMATCH`, `REQUEST_OUTCOME_UNCERTAIN`, and `REQUEST_REPLAY_UNAVAILABLE` require independent reconciliation; best-effort `post_commit` is not a durable receipt. A changed controller identity-provider registration, even with equal issuer/subject claims, also denies retry. A changed/stale/terminal replay, second workload, expired window, or uncertain deduplication denies and triggers quarantine/operator reconciliation. An unresolved gateway admission never expires; a new request ID or a single absent `GetSandbox` result cannot bypass it. [v0.1.5 request ID contract](https://github.com/NVIDIA/OpenShell/blob/v0.1.5/proto/openshell.proto#L1172-L1196), [API error and replay semantics](https://docs.nvidia.com/openshell/v0.1.5/sdk/api-errors#durable-request-admission).

The interceptor and catalog must cover every route-affecting unary write the pinned gateway exposes, including provider/profile create/update/import/delete, attach, sandbox policy and workspace/global configuration mutation. A direct profile write using valid provisioner authority must be denied or proven inert in the authoritative catalog and effective policy. An external value/refresh update of an attached direct-source provider is denied; same-scope automatic refresh is eligible only with the separate issuer/upstream proof under CR-0008. A controlled widening drains/deletes **all affected running and stopped private sandboxes** and observes absence before the change. Later `ExposeService`, non-interceptable lifecycle RPCs, and driver mounts require separate effective denial/verification because an interceptor for unary writes alone cannot cover them. The model and broker remain closed until exact policy/provider and current-attempt receipts pass.

## Required allow and deny behavior

- **Accept:** An exact signed create with approved inline spec, profile catalog, provider instances, policy, and no external mount/service exposure reaches **one** sandbox whose immutable ID, persisted spec, actual Pod/PVC/services, effective loaded policy, and provider receipt all match. A lost response may be recovered by `GetSandbox` or a bounded, byte-identical same-`request_id` retry under the same current attempt, signed intent, and qualified gateway deduplication window; it returns only the original ID. Only after independent reconciliation does the current attempt become ready. A reviewed route change applies only after every affected old private sandbox, including stopped ones, is observed deleted and a new attempt is admitted.
- **Deny:** Altered, expired, stale-attempt, terminal, or second-create intent replay; same-image/name create with changed command, environment, restart/runtime/resources, metadata, reused provider name pointing to a different instance, profile digest, credential generation, policy, template, driver config, foreign PVC/host mount, or service exposure; unknown protobuf field; direct valid-token profile mutation; attached direct-provider external value/refresh mutation; workspace/global widening before drain; later `ExposeService`; old stopped-sandbox restart; worker access to a new endpoint or unapproved path on a supervisor-reachable gateway/issuer/telemetry host; direct Pod bypass. Denial occurs before private source/model traffic, including on uncertain create and recovery.

## Dependencies, risk, and disable path

Depends on positive SEL selection, chosen OpenShell gateway/supervisor/runtime/controller and node/CNI versions, [CR-0015](CR-0015-phase0-attempt-identity-readiness.md) readiness, pinned catalog source and signing key custody, gateway extension registration, and approved owner roles. The threat is a valid privileged RPC widening a private worker route or a create/mount/service field bypassing the job partition while a job is active. A watcher after policy sync is containment, not the admission gate. Qualify every relevant v0.1.5 or upgraded RPC; if an ungoverned path remains, keep private stages disabled. Pause admissions, quarantine source/model egress, revoke affected attempt identities, stop and observe deletion of old sandboxes, and roll back the gateway/catalog/policy as a matched versioned set if a mutation or drift is observed. The separate conditional [CR-0020](CR-0020-supervisor-middleware-route-gate.md) / [ToDo](../todos/CR-0020-supervisor-middleware-route-gate.md) tracks a supervisor middleware route decision service if the preferred native/interceptor composition fails; it does not waive full-create, profile, mount, or service controls.

## Closure gate

The paired ToDo must link versioned internal intent/mutation contracts and allowed/denied fixtures, component/configuration PRs, signing/catalog/extension ownership, exact gateway descriptor and image/policy/profile digests, controller/readiness integration, live privileged-RPC and runtime/CNI allow/deny evidence, active/stopped-sandbox drain, restore/rollback, and independent platform/security review. Documentation or a rendered policy does not close this CR. No private stage runs until this gate and the other applicable Phase 1 gates pass.
