# Change request and ToDo index

This is the discovery index for design impacts. Each impact has a change request (CR) describing the required change and a paired ToDo containing executable tasks and evidence. The CR and ToDo carry the current matching **Status**; this index does not duplicate their acceptance criteria or status. The [design-change workflow](../AGENTS.md#design-change-impact-gate) requires a pair for every identified impact and direct links from the affected design and README. Keep pairs linked here after closure for audit.

The source-authentication impacts come from [ADR 0001 and its impact analysis](decisions/0001-outbound-mcp-source-tokens.md#impact-analysis-and-document-disposition); the workflow impact comes from [ADR 0002](decisions/0002-design-impact-traceability.md#impact-analysis). The [implementation plan](design/implementation-plan.md) records build-input and Milestone 0 intake, the [local model-route impact](design/implementation-plan.md#7-local-model-route-impact-analysis), and the [phase-specific identity intake](design/implementation-plan.md#8-proof-boundary-reconciliation-and-identity-intake). The [research design](design/research-and-evidence.md#production-provider-adapter-and-route-catalog-impact) tracks the separate production provider seam; the [feasibility design](feasibility-and-market-assessment.md#chatgpt-baseline-connectivity-impact) tracks the ChatGPT fixture tunnel; the [deployment design](design/deployment-and-operations.md#private-stage-route-governance-implementation-impact) tracks mandatory private route governance and its deferred middleware fallback. The [progress report](progress-report.md) records current work. Open and deferred component pairs are obligations, not running controls.

A pair becomes **Verified** only when its required change and proof are recorded in both files and the design is reconciled. For an implementation impact, that means the named component or configuration change plus positive and negative evidence on pinned versions; documentation-only impacts need document review and checks. A deferred option stays visible until selected or explicitly **Withdrawn** with a decision that updates the intended design. Every implementation pull request links its pair and reports any new impact back into the analysis.
