## Findings and corrected contract

Line anchors for the scenarios below: `docs/design/matched-evaluation-contract-v3.md:38-46`, `docs/change-requests/CR-0025-candidate-citation-provenance.md:20-31`, `eval/target_projection.py:370-382`, `eval/schemas/packet-manifest.schema.json:7-21`, and `eval/blind_review/tool.py:483-512,1536-1573`.

| Severity and original failure scenario | Corrected proposal and required negative proof |
|---|---|
| **Important — wrong-case or switched manifest member could pass a merely hash-consistent attestation.** The original wording checked an expected attestation `case_id`, packet raw hash, and manifest membership without explicitly equating the packet's own case, the manifest member hash, and the approved case view. The existing target derivation selects the case from the packet itself. | [V3 lines 42–44](../design/matched-evaluation-contract-v3.md#candidate-citation-provenance-precondition) now require `packet.case_id == attestation.case_id == independently expected case_id`, exact approved question and ordered visible source snapshots, all manifest packet IDs distinct, packet count equal to list length, and the unique target member hash equal to both the attested hash and actual packet SHA-256. Deny a different valid case packet under the signed cell, a non-target duplicate ID, a changed member hash, out-of-view citation, changed source view, or candidate-label field even when an attacker re-signs internally consistent bytes. |
| **Important — a self-consistent partial manifest is not a complete benchmark matrix.** A valid manifest `packet_count` and unique list cannot show that all approved candidate×case cells and noncompleted dispositions were prepared before selective packet delivery. A later witness signature cannot prove earlier ordering. | [V3 lines 40 and 46](../design/matched-evaluation-contract-v3.md#candidate-citation-provenance-precondition) require an independent pre-delivery comparison of the manifest packet set with all raw observations, concealed completed assignments, and reviewed noncompleted dispositions for the approved matrix. The isolated helper deliberately cannot perform that custody check. Deny a missing completed packet or a post-delivery addition even if the local manifest parses and signs. |
| **Important — the original 32 KiB attestation could not represent every valid packet citation array.** Current packet rules allow up to 32 source-exact citations and a 128 KiB packet, while the draft attestation duplicated the complete citation array under a 32 KiB ceiling. “Sorted-key compact UTF-8” also left non-ASCII encoding ambiguous. | [V3 line 42](../design/matched-evaluation-contract-v3.md#candidate-citation-provenance-precondition) now signs `citation_count` and `citation_spans_sha256`; the ordered array remains in the hash-bound packet and restricted extraction record. SHA-256 is recomputed from `json.dumps(..., ensure_ascii=False, sort_keys=True, separators=(",", ":"), allow_nan=False).encode("utf-8")`, without Unicode normalization. Deny changed, reordered, added, dropped, duplicate, non-source-exact, or out-of-view spans, including non-ASCII variants. Enforce 32 citations, 32 KiB exact JSON, 8 KiB detached signature, and 128 packet records. |
| **Important — key pinning and a signed time reference alone do not confer control-review authority or prove delivery order.** The fixed `openssl dgst -sha256 -verify` command verifies bytes for the supplied public key; it does not qualify algorithm/strength, signer role, key validity, revocation, or event time. A signed time reference could point to an unrelated earlier log entry. | [V3 line 46](../design/matched-evaluation-contract-v3.md#candidate-citation-provenance-precondition) assigns the future distributor an independently pinned `control_reviewer_id`→key digest/role/algorithm/window register, actual RSA-3072-or-stronger qualification, role separation, current revocation check, and independent append-only evidence binding exact preliminary JSON/signature digests to packet/target delivery IDs and reviewer-edge received bytes in order. The isolated verifier checks the separately supplied raw key SHA-256 and exact domain-separated signed payload only; a self-computed pin or timestamp is not independent authority. Deny missing or revoked key, wrong role, reused log reference, late signature, and changed delivered bytes. |
| **Important — an uncheckable native link could be silently dropped or spuriously deferred.** Requiring every native reference to become a source-exact packet span conflicted with the rule that an uncheckable but otherwise completed answer remains scored unsupported. Treating an out-of-view reference as merely unsupported would hide a source-control violation. | [V3 line 38](../design/matched-evaluation-contract-v3.md#candidate-citation-provenance-precondition) now requires a versioned extraction record to account for every native reference as faithfully `mapped`, `unmappable_unsupported` in allowed context, or `out_of_view_control_violation`. Only faithful mapped spans enter the packet. A complete faithful accounting can be `corroborated` even if an allowed native link is uncheckable; it earns no support. An invented, omitted, changed, or forbidden-source reference blocks. Product-specific extraction and these fixture outcomes remain to be implemented and independently observed. |
| **Important — two preliminary decisions for one cell could allow selective replacement of a block.** The initial per-cell signature rule did not say whether a later favorable signature could displace a blocked one. | [V3 line 46](../design/matched-evaluation-contract-v3.md#candidate-citation-provenance-precondition) now requires one active decision per cell, retention of every prior signed decision, and documented supersession through a new frozen attempt and distinct run/packet/manifest identities before either delivery. Deny silent replacement of a blocked decision and any attempted correction after delivery. |

The exact v1 field set, `blocked`-only bounded `reason`, duplicate/extra JSON-key rejection, nonfinite/invalid-UTF-8 denial, and `b"openshell-deep-research/pre-distribution-citation-attestation/v1\n" + exact_attestation_json_bytes` signature payload are now specified in the [primary design](../design/matched-evaluation-contract-v3.md#candidate-citation-provenance-precondition) and [strict schema](../../eval/schemas/pre-distribution-citation-attestation.schema.json). The helper must compare independently supplied candidate, case, run, packet, and control-reviewer expectations, approved raw corpus/source/rubric pins and canonical digests, original/extraction raw hashes, and exact packet/manifest identities. Its success must remain a binding result with no distributor capability. Candidate-labeled attestation/extraction material and all diagnostic output stay out of the anonymous packet and reviewer target view.
