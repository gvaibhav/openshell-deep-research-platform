## Blocker: an intermediate output-path symlink can redirect publication into the verified blind packet directory

`eval/scorecard.py:1509-1524` validates a fresh absolute output name and resolves it outside the signed packet directory. At `eval/scorecard.py:1535-1539`, it opens `path.parent` by its **original pathname** with `O_NOFOLLOW`; that flag protects only the final path component. It does not prevent an intermediate ancestor symlink from changing between validation and `os.open`. The opened directory FD is never compared with the directory resolved at validation or proved outside the packet tree before the temporary file and exclusive hard link are created at `eval/scorecard.py:1545-1566`. The final catalog check covers the signed artifact paths, not the output parent's actual opened inode. This is a time-of-check/time-of-use path substitution across the blind-label boundary.

I independently reproduced it with `SignedFixture` and valid local witness/control signatures. The signed artifacts were under a separate `approved/` directory. The caller's output was `attacker-controlled-output-path/route/packets/scorecard.json`, with intermediate symlink `route` initially pointing to `benign/`; `benign/packets/` was an ordinary directory. A deterministic hook changed only `route` to point to `approved/` immediately before the first `os.open(path.parent, ...)`. Both validations had accepted the benign resolution. The program returned **0**, created mode-**0600** `scorecard.json` inside the **verified** `approved/packets/` directory, and its content said `ready_for_human_decision`. The benign directory remained empty; stderr was empty. The hook models an actor able to mutate only its output-path symlink while the more privileged scorer owns the signed packet directory. No signed, catalog, run, or packet byte was changed.

**Required correction and denial proof:** Bind validation and publication to the **same opened output-parent directory identity**, and prove that opened directory is outside the verified blind packet tree before writing or linking. Reject a symlink or rename switch in any output-path ancestor, not just the final component. The proof must survive an A→B→A path switch after the first check and a switch that stays at B; a deterministic hook immediately before `os.open(path.parent, ...)` must return 2, leave both packet and benign directories without a scorecard or temporary file, and preserve all signed inputs. Keep the fresh exclusive mode-0600 allow case. An operator-controlled private output root, opened by FD through no-follow components and held through publication, is a simpler acceptable contract if it is enforced and documented. A pathname-only post-check after `os.open` is insufficient because the FD may already refer to the packet directory. Re-review the resulting implementation independently.

## Original catalog finding: corrected in this local scope

`eval/binding.py:44-53,72-120` now captures one immutable `BindingCatalog` containing exact raw bytes, file and parent stamps, selected paths, and resolved paths. `eval/scorecard.py:1478-1489,1607-1646` passes that **same** catalog to output exclusion and `build_scorecard`; `eval/binding.py:169-200` uses its resolved paths for the signed verifier, and `eval/binding.py:123-137,331` checks for drift. Thus a changed catalog cannot independently select packet directory B for verification while output exclusion retains A.

I reran the prior signed A→B→A counterexample using an exact copy of the valid packet directory and output under B: exit **2**, no B output; verification rejected on the second catalog read. The same-path raw-byte-drift A→B→A and a change that stayed at B each returned **2** with no output. The targeted resolved packet-path symlink switch test and stable fresh-output test passed. A stable valid bundle published an exclusive mode-0600 scorecard; a reused/stale name and a direct packet-directory output were denied. These results close the **catalog-selected-path** reproduction only. They do not address the output ancestor race above or prove protection against an attacker who can mutate an untrusted output path.
