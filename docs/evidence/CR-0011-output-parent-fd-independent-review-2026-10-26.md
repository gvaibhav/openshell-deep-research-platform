## Blocker: verifier can read packet directory B while output exclusion holds A

`eval/scorecard.py:1700-1727` opens and retains output and packet-directory FDs **before** scoring. Its packet-tree exclusion at `eval/scorecard.py:1623-1646,1681-1690` compares the output FD with the retained packet FD and later checks that the retained packet pathname resolves to that inode. However `eval/binding.py:182-200` still calls `verify_signed_bundle` using a **pathname**, not the retained packet FD. `eval/blind_review/tool.py:803-877` then opens and lists the packet directory by that pathname. The packet path can point temporarily to a different exact signed copy during verification and return to A before the post-verification path/FD checks. The output FD can therefore be outside held A yet inside the **physically verified B** directory.

I independently reproduced this with a valid signed `SignedFixture` 3×20 matrix. I moved packet directory A into a separate `selector-parent/packets`, updated only the untrusted binding path catalog, and made an exact packet-directory copy B at `reviewer-parent/packets`. The CLI opened output target `B/scorecard.json` and retained packet FD A. A deterministic hook around the actual `verify_signed_bundle` call temporarily renamed `selector-parent` and replaced it with a symlink to `reviewer-parent`, then restored A immediately after real signature verification. During verification, the passed A pathname resolved to B; `_packet_manifest` saw B as a real directory and verified its exact signed bytes. With all paths restored, the catalog check and held-FD ancestry check passed. The CLI returned **0** and wrote a `binding.status: verified_local`, `decision_readiness: ready_for_human_decision` labeled scorecard **inside B**; A contained no scorecard and stderr was empty. No signed packet, review, receipt, control, run, or source byte changed. This reproduces the same pre-reveal label leak as the earlier [catalog review](CR-0011-catalog-race-final-review-2026-10-26.md), now through the packet path rather than the output path.

**Required fix and deny proof:** Signed packet reads, listing, and output-tree exclusion must use the **same pinned physical directory**. Pass the held packet-directory FD into verification and perform packet file reads/listing relative to it with no-follow semantics, or otherwise enforce an equivalent FD-bound immutable packet snapshot; checking a pathname before and after is insufficient for A→B→A. Red/green an exact signed B copy selected only during verification, then restored before publication; require exit 2 and no scorecard/temp file in either directory. Also test a switch that remains at B, a nested symlink/rename, direct packet-output alias, and stable valid publication. Keep packet distribution and scored SEL disabled until this is corrected and independently re-reviewed.

## Output-parent correction: locally supported in its narrower scope

`eval/scorecard.py:1552-1597` captures the lexical route and requires an owner-UID, exact mode-0700 ancestor. `eval/scorecard.py:1605-1620` opens resolved directories one component at a time with no-follow flags. The scorer holds the output FD from pre-verification through mode-0600 temporary creation and exclusive hard-link publication (`eval/scorecard.py:1700-1787,1821-1863`). It checks the opened output inode against both lexical and resolved parents, rejects consumed-input aliases and the **held** packet FD ancestry, and checks path/stamp drift. My separate replay of the original attacker-controlled intermediate output-symlink switch returned **2**, no packet or benign output/temp file, with `scorecard output parent changed during evaluation`. The stable fresh-output, A→B→A, parent-rename, changed-stays-B, nested symlink, collision cleanup, and reused-name tests passed locally. This supports the output-parent fix only when the packet FD is the one the verifier actually reads.
