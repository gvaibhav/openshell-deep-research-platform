## Contract and red/green proof

The release validator now requires the Trivy 0.76.1 CycloneDX **root component** to contain exactly one valid `aquasecurity:trivy:ImageID` equal to the vulnerability report and Docker inventory image ID. It requires a complete valid multiset of `aquasecurity:trivy:DiffID` properties equal to the report and inventory rootfs DiffIDs. The report's `Metadata.DiffIDs`, image-config `rootfs.diff_ids`, and Docker inventory remain equal **in layer order**. The observed CycloneDX properties are sorted, so their order is not used as layer order. Missing, malformed, duplicate, extra, or mismatched root identity properties fail promotion even when the SBOM evidence checksum has been recomputed. Other well-formed Trivy root properties remain allowed.

The three new denial methods initially produced **12 expected failures** against the former validator: missing all/ImageID/DiffID properties; wrong well-formed ImageID/DiffID; malformed property list, entry, ImageID, or DiffID; duplicate ImageID/DiffID; and an extra DiffID. The fixture's positive case uses two rootfs layers in unsorted scan/Docker order and sorted SBOM properties, matching the observed Trivy 0.76.1 structure. After the correction, the four focused positive/negative methods passed, and the full `scripts.build_security` suite passed **103 tests** on pinned local Python 3.13.17. The repository `make test`, `make lint`, `make typecheck`, and `make lockcheck` also passed. `git diff --check` passed. A concurrent new CR-0024 pair was incomplete when `make check` ran, so that run failed on CR-0024 README/index/primary-design links; it did not report a CR-0013 or this evidence-file defect. Re-run `make check` once that separate pair stabilizes.
