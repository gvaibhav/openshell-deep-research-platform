## Findings and recheck

1. **Important, resolved — distinguish app creation from tester use.** The initial handoff owner row did not name an effective custom-MCP app creator permission or authorized admin creation separately from the tester's install/use permission. In the revised [handoff:27](../handoffs/chatgpt-mcp-admin-request.md), the workspace owner must provide one of those creation paths and separately permit tester use. The [CR:16](../change-requests/CR-0018-chatgpt-synthetic-mcp-baseline.md) and [ToDo:25](../todos/CR-0018-chatgpt-synthetic-mcp-baseline.md) now carry the same dependency. Current [custom MCP instructions](https://developers.openai.com/api/docs/guides/custom-mcp-server) and [tunnel instructions](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels) state workspace permissions for adding and using custom MCP. Neither opened page establishes a universal separate developer-mode entitlement, so the handoff requests it only if this workspace requires it.
2. **Important, resolved — assign tunnel Use to the app creator.** The initial Platform row assigned Tunnels Read + Use to a runtime/app operator without saying the designated workspace app creator must hold it to select the tunnel. The revised [handoff:28](../handoffs/chatgpt-mcp-admin-request.md), [CR:16](../change-requests/CR-0018-chatgpt-synthetic-mcp-baseline.md), and [ToDo:25](../todos/CR-0018-chatgpt-synthetic-mcp-baseline.md) explicitly grant Tunnels Read + Use to that creator and any separate runtime operator, while Tunnels Read + Manage is scoped to tunnel setup. This matches [OpenAI's tunnel role and workspace-association rules](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels).

No remaining scoped Blocker or Important finding was found in the revised owner request. The handoff asks for nonsecret identifiers, permissions, approval references, and observations; it does not imply the user's Mac app controls grant workspace or Platform roles. The [desktop MCP guidance](https://learn.chatgpt.com/docs/extend/mcp) describes shared local Codex-host configuration and a separate hosted plugin path; [Work Local availability](https://learn.chatgpt.com/docs/use-chatgpt) depends on account/workspace enablement. The handoff correctly labels a local Work-mode call as conditional compatibility evidence and a Codex-only call separately. It requires actual Deep Research source selection and tool calls before a hosted MCP score.
