## Findings and disposition

**No remaining scoped Blocker or Important** was found in the isolated binding-only helper. Successful verification returns `None`, not a capability or artifact. The only filesystem writes are private temporary copies of the public key and detached signature for the existing pinned OpenSSL verifier. Reviewed code and a synthetic private-content canary probe showed no candidate/input value in the returned exception text, stdout, or stderr.

**Nonblocking contract precision, documented and tested:** JSON Schema Draft 2020-12 treats mathematically integral JSON numbers as integers, so schema preflight admits `schema_version: 1.0` and integral `citation_count: 2.0`. The runtime's exact Python `int` checks at `eval/pre_distribution_attestation.py:202,220` deny both **even when the changed attestation is freshly signed**. The schema description, primary design, CR/ToDo, and evaluation guide now say schema validation is only preflight and exact-byte runtime verification is mandatory. The follow-up signed numeric-spelling test passed 2/2 cases. This was a green-only follow-up to the existing stricter code; no pre-correction red result is claimed.

The helper accepts already materialized `original_artifact_bytes` and `extraction_record_bytes` solely for SHA-256 binding at `eval/pre_distribution_attestation.py:376-387`. No live or externally reachable caller, privileged side effect, data return, or log path exists in this isolated slice. This is a **required future ingress gate**, not a present local authorization bypass: before distributor integration, its file readers must choose numeric per-product byte limits, reject oversize **before** materializing helper bytes, and test content-free denial. The [paired ToDo](../todos/CR-0025-candidate-citation-provenance.md) now records that obligation. An arbitrary cap in the unused helper could reject a legitimate product artifact before extraction profiles are fixed.
