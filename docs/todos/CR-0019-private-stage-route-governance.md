## Implementation and proof checklist

- [ ] After the SEL decision, name platform/security/controller owners and choose/pin gateway, supervisor, runtime, controller, protobuf descriptor, node/CNI, policy/profile source, signing key, and extension binding versions. Inventory **every** route-affecting RPC in that version; record which are interceptable and separately controlled. If any relevant route has no gate, keep private stages disabled.
- [ ] Before dependent code, write and review `contracts/internal/private-stage-route-intent.schema.json` plus allowed and denied fixtures. Specify deterministic canonicalization of the **entire effective post-patch** `CreateSandboxRequest`, unknown-field handling, one logical-create intent ID and durable ledger state binding the controller identity-provider registration/issuer/subject, workspace/name/request ID, metadata, all inline spec fields including provider names, a separate signed expected name→immutable provider ID/resource-version/profile-digest/credential-generation map, matching post-create desired-identity receipts, and explicit absence of template, driver config, and service exposures. Pin a retry count/interval shorter than the qualified gateway replay window; only the same authenticated controller identity-provider registration, issuer, and subject, RPC/workspace, current attempt, nonzero UUID request ID, original/effective bytes, stable interceptor transformation, and signed map may retrieve an uncertain original result. Do not use best-effort `post_commit` as a durable receipt; define operator reconciliation for unresolved admissions, which never expire. Add compatible mutation/receipt contracts or a versioned format migration plan when required.
- [ ] Write failing TDD cases for correct logical-create intent and persisted receipt, identical same-`request_id` uncertain-response retry returning the original sandbox ID with replay metadata, changed/stale/terminal/expired replay and second-create denial, `REQUEST_ID_PAYLOAD_MISMATCH`/`REQUEST_OUTCOME_UNCERTAIN`/`REQUEST_REPLAY_UNAVAILABLE` quarantine, changed interceptor transformation, and same ID from another controller identity-provider registration (including equal issuer/subject claims) or another issuer/subject denial, any changed/unknown create field, same-profile different provider instance, provider-name reuse resolving to a different immutable ID/version, unauthorized profile import/update with a valid provisioner token, attached direct-provider external value/refresh update, workspace/global widening while old sandbox lives, later `ExposeService`, stopped-sandbox restart, wrong worker path on a supervisor-reachable host, and direct Pod bypass.
- [ ] Implement the operator-owned fail-closed gateway interceptor and authoritative trusted profile catalog, including gateway extension registration and startup fail-closed check. The provisioner API still rejects profile writes; a **direct** valid-token profile RPC must be denied or inert. Never use application API refusal as native RPC denial proof.
- [ ] Bind the returned immutable sandbox ID to the signed intent, re-read the full persisted spec, inspect actual Pod/PVC/service inventory and external mounts, then inspect the loaded effective policy and provider receipts before any Job API, broker, model, or direct-source readiness. Uncertain create, timeout, normalization drift, or missed receipt stays closed and triggers reconciliation/deletion.
- [ ] Qualify a controlled route/profile/policy change across all affected running **and stopped** private sandboxes. Fence credentials/egress, delete and observe absence before widening, then re-admit a new attempt. Prove active streams and old stopped-sandbox restart do not retain source/model access during rollout, restore, or rollback.
- [ ] On the exact deployed cluster, run independent CNI ingress/egress canaries, worker direct-bypass denial, supervisor shared-host/path denial including existing connections, gateway/provider privileged-RPC denial, foreign PVC and service exposure denial, and an approved route allow case. Repeat after relevant gateway, interceptor, catalog, policy, node/CNI, or provider change. A policy object or local mock is insufficient.
- [ ] Resolve an independent OpenShell/platform/security review and attach source commit, implementation PRs, signed intent/catalog/policy digests, image/SBOM/CVE evidence, observed allow/deny logs, owner approvals, release/disable path, and as-built architecture/design reconciliation. Keep this pair `Open` until both implementation and proof pass.
