# Connector MCP broker

Future trusted service outside OpenShell. It authenticates the sandbox job identity, loads the server-held job policy, validates each tool and its arguments, obtains the correct user or application grant for the requested source, calls the upstream MCP server or API, and records auditable provenance.

It is intentionally a narrow tool service, not another research agent. Provider tokens and refresh credentials stay in its vault or cloud identity system. See [MCP connector design](../../docs/design/mcp-connector-broker.md) and [identity and access](../../docs/design/identity-and-access.md).

The BFF Connection API handles the public callback, then relays code, state, and its verified session binding over an authenticated internal channel. The broker owns the one-use state and PKCE verifier, code exchange, source identity check, connection record, and token vault; it returns only an opaque reference and display-safe metadata to the API. Before storing a user-delegated grant, it verifies the source-authenticated person against the dashboard subject through an approved issuer-qualified, immutable account link; OAuth state and PKCE do not establish that match. Each connector declares its exact MCP resource, issuer, target binding, read scopes, user or approved app principal, renewal, and revocation. A separate Okta OBO exchange or Okta for AI Agents STS/XAA path is conditional and must pass the source-specific gates in the [Okta handoff](../../docs/okta/requirements-and-design.md#6-outbound-source-token-choices-and-oktas-conditional-role). The broker's planned changes are [identity CR-0002](../../docs/change-requests/CR-0002-source-identity-binding.md)/[ToDo](../../docs/todos/CR-0002-source-identity-binding.md), [adapter CR-0004](../../docs/change-requests/CR-0004-oauth-mcp-adapter.md)/[ToDo](../../docs/todos/CR-0004-oauth-mcp-adapter.md), and [custody CR-0005](../../docs/change-requests/CR-0005-grant-custody-revocation.md)/[ToDo](../../docs/todos/CR-0005-grant-custody-revocation.md); optional token-flow pairs are in the [impact register](../../docs/decisions/0001-outbound-mcp-source-tokens.md#actionable-impact-register).
