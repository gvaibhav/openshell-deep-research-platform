# Dashboard API

Future authenticated dashboard API and internal job API. This directory is reserved for the service that accepts user requests, validates selected connections and resources, records immutable job policy, and serves job status, events, reports, and evidence to the dashboard. The [controller](../../services/controller/README.md) owns queue dispatch and OpenShell sandbox lifecycle.

The API must authenticate users with Okta Authorization Code with PKCE through a BFF session, enforce CSRF protection for mutations, and never accept `tenant_id`, `user_id`, model entitlement, or authorization scopes as trusted browser claims. It validates the untrusted `visibility_selection` against the submitter's active Okta membership, selected tenant, and approved group publishing policy, then creates a separate server-held access policy. Every list page, status/event stream, report, evidence, and artifact read is authorized against that policy; private content additionally requires current source entitlement. A separate internal endpoint authenticates the current sandbox attempt before returning its narrow stage manifest or accepting events and artifacts. See [job lifecycle](../../docs/design/job-lifecycle.md), [identity and access](../../docs/design/identity-and-access.md), [research visibility](../../docs/design/research-visibility.md), and the [OpenAPI sketch](../../contracts/openapi.yaml).

Initial endpoints to implement: job submission with individual or approved-group visibility, per-job group-audience revocation, authorized listing/getting, event streaming, cancellation, connection management, and artifact retrieval. Request and output shapes begin in [contracts](../../contracts/README.md).

For a user-delegated source connection, the BFF Connection API starts from a verified dashboard session and owns the registered public OAuth callback. It rechecks that session at callback and relays the authorization code, one-use state, and session binding to the broker over an authenticated internal channel. The broker owns PKCE state, code exchange, source identity matching, and the token vault; the API receives only an opaque `connection_ref` and display-safe metadata. A dashboard-A/source-B callback must fail even with valid state and the same tenant. The API presents reauthorization and disconnect without returning source tokens; the broker enforces grant expiry and source-call revocation. The API obligations are [contract CR-0001](../../docs/change-requests/CR-0001-source-connection-contract.md) with its [ToDo](../../docs/todos/CR-0001-source-connection-contract.md), and [identity-binding CR-0002](../../docs/change-requests/CR-0002-source-identity-binding.md) with its [ToDo](../../docs/todos/CR-0002-source-identity-binding.md), under the [revised identity design](../../docs/design/identity-and-access.md#oauth-protected-mcp-design).
