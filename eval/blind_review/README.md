# Synthetic blind review packet custody

**Status:** Disposable CR-0011 tooling for synthetic/public cases. The checked-in corpus and rubric are still pending human approval, and no candidate run or independent witness receipt exists. This utility does not make a platform-selection decision or enable a production feature. See the [change request](../../docs/change-requests/CR-0011-matched-feasibility-evaluation.md), [paired ToDo](../../docs/todos/CR-0011-matched-feasibility-evaluation.md), and [evaluation guide](../README.md).

The custodian prepares a random-order set of reviewer packets for **completed** candidate×case cells from approved case/source/rubric digests and raw observations. Deferred and failed cells carry a bounded reason and retained evidence reference; they have no answer packet or quality score. A separate owner-only map retains candidate labels, run IDs, screening records, and noncompleted dispositions. Reviewers see only completed-case questions, screened answers, approved visible source snapshots, and exact citation spans. The unblind command checks the full candidate×case union, a separately signed control review, and the witness's signed freeze of the exact artifact bytes before writing the labeled assembly.

~~~mermaid
flowchart LR
    A[Approved case, source, rubric digests] --> C[Custodian prepares packets]
    B[Raw completed observations<br/>and noncompleted dispositions] --> C
    C --> P[Random-ID completed-cell packets]
    C --> M[Owner-only map of all cells]
    P --> R[Blind human reviews]
    R --> L[Custodian assembles labeled<br/>candidate-run v2 rows privately]
    M --> L
    L --> V[Independent control reviewer<br/>signs raw-run and control evidence]
    V --> W[Independent witness signs exact<br/>manifest, map, review, control hashes]
    R --> W
    M --> U[Verify signed freeze and unblind]
    W --> U
    U --> S[Later scorecard assembly<br/>and observed-run corroboration]
~~~

## Custody sequence

1. Human reviewers approve the exact 20–30-case corpus, source pack digest, and rubric before the matched runs. The utility refuses a pending corpus or rubric. Keep expected answers, preregistered citation spans, forbidden source text, permission targets, and candidate metadata with evaluators.
2. Record one v2 raw-observation cell for each approved candidate×case: a completed run whose `raw_answer` and `packet_answer` have **identical UTF-8 bytes**, or a deferred/failed disposition with a reason of at most 2048 characters and an evidence reference plus SHA-256. A noncompleted cell has no run ID, answer, metrics, citation, or score. For completed cells, the custodian checks the actual raw answer for identity or unauthorized-source leakage and records a screening reference, custodian, time, and hashes of the same answer bytes. Do not redact or repair an answer for blind scoring. Quarantine an identity leak, retain the original attempt, and obtain an independently evidenced disposition or a new approved blind-safe run; readiness remains incomplete until coverage is valid. An unauthorized source disclosure is a control violation and cannot be hidden as a deferral. The tool rejects obvious candidate identifiers and exact unadmitted source IDs or full source text. Human screening remains necessary for subtler self-identification, paraphrases, short excerpts, and semantic source leakage.
3. Run the preparation command with **canonical physical absolute**, distinct output paths; no output-route component may be a symlink. On macOS, resolve `/var` to `/private/var` before passing a path. The reviewer packet directory is created at mode 0700, its completed-cell packet files and manifest at mode 0600. The concealed map is created at mode 0600 inside a different owner-only mode-0700 directory. An output route needs an effective-UID-owned exact mode-0700 private ancestor; every component must be root- or effective-UID-owned, and a group/world-writable containing directory must be sticky. A writable nonsticky parent is rejected even if its child is mode 0700. Preparation pins the map and packet parent routes before creating either artifact, then holds their directories open. It compares the new packet directory inode with its opened descriptor before writing packet files through that descriptor. It only cleans up its own identified artifacts after a failure; leave uncertain artifacts for operator reconciliation. Share only a controlled copy of the packet directory with blind reviewers. Keep the map, raw observations, dispositions, screening records, and answer artifacts outside their access. Preparation can create an incomplete draft; unblind requires the union of completed assignments and noncompleted dispositions to equal every approved candidate×case exactly once.
4. Reviewers submit scores against exact packet IDs and packet SHA-256 values; candidate-run v2 assembly requires **exactly one quality review for each completed packet** and none for deferred/failed cells. While labels remain restricted, the custodian assembles every labeled candidate-run v2 result from the map, raw observations, dispositions, and submitted blind quality scores. A separate control reviewer inspects those complete files, labeled raw runs, screening, source/tenant permission events, prompt-payload delivery, answer inspection, and each noncompleted evidence claim. That reviewer signs [control-review v2](../schemas/control-review.schema.json), including a canonical digest of every complete candidate-run v2 object, a separate control evidence reference for each noncompleted cell, and the approval basis `independently_retained_raw_run_control_and_disposition_evidence`, with a key independently registered apart from the witness key. A noncompleted cell cannot count as a tested denial. Blind quality reviewers do not see the map, labeled runs, or control review.
5. A separate witness checks that the completed packet assignments plus noncompleted dispositions cover every approved candidate×case, then signs [receipt v3](../schemas/witness-receipt.schema.json) over exact manifest, map, raw-observation, blind-review, control-review, and control-signature **file hashes**, cell/packet/disposition counts, signer IDs, and public-key digests before labels are released. Both signing keys and the witness's independently auditable timestamp record must be controlled outside the packet custodian and label-release process. Expected IDs and trusted key digests come from an independently approved register, not the path catalog, map, or packet preparer. Earlier receipt versions are rejected by this release protocol.
6. Run unblind using independently held approved corpus/source/rubric files, both pinned public keys, signed receipt, signed control review, and the same artifact bytes. Unblind pins the output route before alias validation and holds the owner-only private output parent and verified packet directory descriptors throughout signed verification and label publication; a changed path or inode blocks release. Preparation and unblind both call the shared evaluator's full input preflight, so a repinned but invalid case/rubric cannot release labels. The verifier compares every completed packet question and complete visible source view with the approved files, as well as their digests, before label release. It also requires every signed blind review to score exactly that completed case's approved rubric dimensions. It rejects missing, duplicated, misclassified, or changed cells; noncompleted answers or scores; missing independent disposition evidence; changed reviews; wrong packet hashes; map mismatch; bad signature; wrong key or signer ID; and review times after the witnessed time. A signed receipt's time is still the witness's assertion: this offline tool cannot independently prove key ownership or actual wall-clock chronology. Preserve the witness's external audit/timestamp evidence before claiming a pre-reveal freeze.
7. Independently corroborate each completed map entry and raw-answer digest against retained candidate/tenant run artifacts, and each noncompleted reason and evidence digest against the source/tenant availability or failure record. The unblinded file is a provenance assembly, **not** a candidate-run v2 file or a passing scorecard. The scorer rechecks the original signed bytes before using any assembled scores; editing the unblinded copy cannot count as a review change.

## Commands

The command uses Python's standard library plus the shared local evaluator. On this qualified macOS development host it verifies signatures with the fixed, root-owned, non-group/world-writable /usr/bin/openssl binary (LibreSSL 3.3.6, SHA-256 49db04c17e3a8c169ebc48a1149d78c165a86c04913203f46b2a14ce7f4a14fc). It also checks the root-owned path and binary digest before execution. A different host or binary update fails closed until a reviewed, pinned verifier is implemented and tested there. The caller cannot select the verifier executable. It accepts no relative artifact paths. These paths are illustrative; the repository's current pending approval fields make preparation fail until an approved copy exists.

~~~bash
python3 -m eval.blind_review.tool prepare \
  --corpus /approved/cases.json \
  --sources /approved/sources.json \
  --rubric /approved/rubric.json \
  --observations /restricted/raw-observations.json \
  --packet-dir /review/packets-001 \
  --map /restricted/blind-001/candidate-map.json

python3 -m eval.blind_review.tool unblind \
  --corpus /approved/cases.json \
  --sources /approved/sources.json \
  --rubric /approved/rubric.json \
  --raw-observations /restricted/raw-observations.json \
  --packet-dir /review/packets-001 \
  --map /restricted/blind-001/candidate-map.json \
  --reviews /review/blind-reviews.json \
  --receipt /witness/receipt.json \
  --signature /witness/receipt.sig \
  --public-key /witness/witness-public.pem \
  --trusted-key-sha256 "$WITNESS_PUBLIC_KEY_SHA256" \
  --expected-witness-id approved-independent-witness \
  --control-review /control/control-review.json \
  --control-signature /control/control-review.sig \
  --control-public-key /control/control-public.pem \
  --trusted-control-key-sha256 "$CONTROL_PUBLIC_KEY_SHA256" \
  --expected-control-reviewer-id approved-independent-control-reviewer \
  --output /restricted/blind-001/unblinded.json
~~~

The CLI prints only counts and artifact digests on success, and a generic rejection on failure. It does not echo answers, source text, candidate labels, paths, or verification subprocess output.

Signature verification stages public keys and signatures in a Python-created private temporary directory before invoking the pinned local verifier. This assumes the host temp root and same-UID custodian process are controlled; the utility does not defend against a hostile process with the custodian's UID mutating that temporary directory. Disable label release when that host custody assumption cannot be met.

## Complete cell-disposition and witness receipt v3 contract

Utility-owned artifact objects use exact fields; unknown utility fields, duplicate JSON keys, and duplicate IDs are rejected. The approved corpus, source pack, and rubric remain subject to the separate evaluator's full contract checks. SHA-256 values are lowercase hex. File hashes cover the **exact UTF-8 bytes**, including any final newline. Input corpus/source/rubric and complete candidate-run v2 digests cover canonical JSON (sorted keys, compact separators, UTF-8, no nonfinite numbers). The limits are 1 MiB per input/review/map, 128 KiB per completed packet, 128 packets, and 240 total cells. A larger or private-data evaluation needs a reviewed new version.

| Artifact | Exact top-level fields | Holder |
| --- | --- | --- |
| [Raw observations v2](../schemas/raw-observations.schema.json) | schema_version, cell_count, corpus_digest, source_pack_digest, rubric_digest, observations | Custodian only; each observation is completed or deferred/failed |
| Reviewer packet | schema_version, packet_id, case_id, question, answer, source_snapshots, citation_spans | Blind reviewers |
| [Packet manifest v2](../schemas/packet-manifest.schema.json) | schema_version, cell_count, packet_count, corpus_digest, source_pack_digest, rubric_digest, packets | Blind reviewers and custodian; only completed cells have packets |
| [Concealed map v2](../schemas/concealed-map.schema.json) | schema_version, cell_count, packet_count, packet_manifest_sha256, corpus_digest, source_pack_digest, rubric_digest, assignments, dispositions | Custodian only |
| Blind reviews | schema_version, packet_manifest_sha256, reviews | Reviewer/witness custody before reveal |
| [Control review v2](../schemas/control-review.schema.json) | schema_version, approval, packet_manifest_sha256, candidate_map_sha256, blind_reviews_sha256, raw_observations_sha256, candidate_run_digests, cases | Independent control reviewer; completed cells bind raw answer, source and probe evidence; noncompleted cells bind disposition and separate control evidence |
| [Witness receipt v3](../schemas/witness-receipt.schema.json) | schema_version, cell_count, packet_count, disposition_count, packet_manifest_sha256, candidate_map_sha256, reviews_sha256, raw_observations_sha256, control_review_sha256, control_signature_sha256, witness_id, witness_public_key_sha256, control_reviewer_id, control_public_key_sha256, witnessed_at | Independent witness; detached signature over exact receipt bytes |
| Unblinded assembly v3 | schema_version, cell_count, packet_count, disposition_count, packet_manifest_sha256, candidate_map_sha256, reviews_sha256, control_review_sha256, control_signature_sha256, raw_observations_sha256, witness_receipt_sha256, witness_id, control_reviewer_id, witnessed_at, assignments, dispositions | Restricted provenance output after verification; the scorer rechecks original signed files and never trusts this file as proof |

Each **completed** raw observation has `status: completed` plus case_id, candidate_id, run_id, candidate_version, model_version, source_delivery, answer_artifact_ref, latency_ms, cost_usd, user_effort_minutes, raw_answer, packet_answer, screening, and citations. **The two answer strings must have identical UTF-8 bytes.** Preparation and signed verification reject normalization, redaction, or claim edits even when both separate screening hashes and all witness/control signatures are valid. Screening has custodian_id, screened_at, record_ref, raw_answer_sha256, and packet_answer_sha256. Each citation has evidence_id, quote, start, and end; the zero-based, end-exclusive span must exactly match that case's visible source text. A packet source snapshot has evidence_id, origin, and text from the approved source pack. No candidate label, model, version, cost, latency, source delivery, expected answer, or forbidden source snapshot is placed in a reviewer packet.

Each **noncompleted** raw observation has exactly candidate_id, case_id, status (`deferred` or `failed`), reason, and disposition_evidence `{ref, sha256}`. Its map disposition carries those same fields. Its signed control-review entry repeats them and adds a distinct `control_evidence` `{ref, sha256}` from the independent reviewer. Neither a noncompleted candidate-run result nor any noncompleted signed cell has a fabricated answer, citation, metric, score, or tested-denial claim. Any noncompleted required cell keeps selection readiness `incomplete`, except a verified violation in another completed cell may hard-block it.

Each completed concealed assignment binds packet_id and packet_sha256 to case_id, candidate_id, run_id, the observation metadata, and its screening record. The verifier also checks that the screened packet-answer hash equals the actual answer in the signed packet. A blind review entry has packet_id, packet_sha256, reviewer_id, reviewed_at, scores, and notes. Scores are integer 0–4 values and must match **exactly** that approved completed case's rubric_dimensions; duplicate reviewer/packet pairs and additional reviewers are rejected under candidate-run v2. A human reviewer still has to judge semantic support. Blind answer packets cannot prove source/tenant permission events or prompt-injection control outcomes. Permission and prompt violation flags need a separately signed control review linked to each completed packet before the witness freezes the scores. The utility does not itself observe upstream source or tenant events.

The current v2 source-exact packet citation is supplied by the custodian and does not prove candidate-native provenance. [CR-0025](../../docs/change-requests/CR-0025-candidate-citation-provenance.md) / [ToDo](../../docs/todos/CR-0025-candidate-citation-provenance.md) require every native reference to be accounted for as faithfully mapped, allowed but unsupported, or forbidden/out-of-view; only mapped spans enter the packet. An allowed uncheckable reference remains completed and unsupported, while a forbidden source blocks. The isolated [v1 attestation verifier](../pre_distribution_attestation.py) binds exact packet/complete-manifest bytes, approved case/question/ordered source view, original/extraction digests, and packet citation **count plus canonical array digest** with a domain-separated signature. It carries no full citation array and has 32-citation, 32 KiB JSON, and 8 KiB signature bounds. Before any packet or target delivery, a separate distributor must prove full candidate×case matrix completeness, independent qualified/unrevoked control-key and raw-input pins, one active decision with retained supersession history, held-FD bytes, and append-only signature-acceptance and reviewer-edge delivery order. Current v2 tools do not implement that distributor, final v3 control/witness freeze, or product extraction; observed citation scoring remains disabled.

The [scorer-binding v2](../schemas/scorer-binding.schema.json) path catalog supplies artifact locations, never authority pins. A scorecard v4 with `binding.status: verified_local` requires exact original signed bytes, the full approved matrix, complete candidate-run v2 digests, and separately supplied witness/control public-key digests and IDs. The scorer snapshots caller JSON before scoring and binding, rejects nonfinite metrics and aggregates, and requires a fresh owner-only `--output` for every supplied candidate run or binding option. It never prints a full candidate scorecard to stdout; parse and validation failures emit only one fixed, content-free line on stderr. An output route must be canonical and symlink-free, have an effective-UID-owned exact mode-0700 ancestor, and have only root- or effective-UID-owned components protected by sticky semantics where an ancestor is group/world writable. The scorer opens the parent through a no-follow component walk before signed verification and holds that directory descriptor through exclusive, atomic 0600 publication. The signed packet verifier reads every packet through the same pinned packet-directory descriptor used for output exclusion. A changed output ancestor or packet directory blocks publication. The output path cannot replace a consumed input or live inside the packet directory. **Consumers must treat the current process exit status and the current invocation's candidate-run/input digests as the success signal; an old ready file at a reused path is never evidence that a later attempt succeeded.** A later invocation that names an existing output path is refused, including when its signed bundle is invalid.

**Migration:** The previous raw-observation, packet-manifest, concealed-map, control-review, and scorer-binding v1 artifacts, witness receipt v2, unblinded assembly v2, and scorecard v3 do not satisfy this signed-partial protocol. Recreate the full v2 cell matrix and obtain new control/witness signatures before unblind or observed scorer readiness. Candidate-run v2 remains the labeled input shape; its deferred/failed reason is now bounded to 2048 characters. The CR-0024 cross-field equality rule adds no schema field or version: an existing signed v2 bundle with different raw and packet answers is rejected, even if re-signed. No witnessed artifact is upgraded in place.

## Limits and disable path

Random IDs and field filtering reduce label exposure; they cannot prove that answer prose, source origins, or writing style are blind. The custodian must quarantine an identity-leaking answer rather than edit its claims for blind review; a separately evidenced noncompleted cell and a new approved blind-safe run may be needed, keeping selection incomplete meanwhile. An unauthorized source disclosure remains a control violation and cannot be recast as an ordinary deferral. A locally generated key or locally asserted time cannot stand in for the independent witness. The tool validates signatures and ordering from supplied artifacts but cannot prove the witness's organizational independence, immutable external timestamp, real candidate entitlement, run provenance, or source authorization.

The local file checks assume an operator-controlled OS identity and private directory ancestry. POSIX `mkdir` does not return a directory descriptor, and inode-checked cleanup is not an atomic defense against a hostile process sharing the custodian's UID. Use separate OS custody for an adversarial co-tenant; withhold packet distribution and label release if that isolation is unavailable.

If approval, screening, witness provenance, packet-to-run corroboration, or later scorer binding is missing, withhold unblinding and the SEL decision. No production capability is controlled by this utility.
